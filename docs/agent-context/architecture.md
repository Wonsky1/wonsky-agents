# Architecture

The canonical collection is `skills/<name>/SKILL.md` plus each skill's scripts and references. `using-dev-pipeline` routes work; Python's `dev-pipeline` specializes `unified-dev-pipeline`. Shared procedures live in their owning skill rather than being redefined by each worker template. Changes to a shared contract must reach its entry points, execution templates and review/completion gates.

`install.py` and `scripts/` install the collection into selected local agent destinations. Runtime copies are downstream outputs; lasting learning belongs in the canonical collection. Synchronization adds skills and records file hashes in `.wonsky-state/`. Conservative installation updates recorded files only when their installed bytes are unchanged; local edits or deletions block the affected unit, and extra or obsolete files remain. Unknown same-name copies require byte equality or an explicit trusted baseline. Existing `AGENTS.md` files are always retained. See the [installation documentation](../../README.md) for conflict reporting, baseline migration and platform limitations.

Repository context is an explicit pipeline deliverable. Useful factual context is written as a clearly marked draft at its intended path and then presented for user review; existing rules and proposed policies require exact approval before edits or activation. Root instructions stay small and this index selects cohesive topics without a fixed length limit. Task plans, test logs and chat summaries do not replace context. Draft review status, exact policy approvals and verified-current evidence travel in handoffs.

`update.py` adds an explicit review flow over original, local and offered skill files. Its preview shows file differences and whole-skill Keep/Use New choices across canonical and runtime destinations; reviewed replacements receive backups before apply. New code remains staged separately until the final plan is confirmed. Unknown originals are identified honestly, and existing AGENTS.md plus unrelated/personal files are preserved. The thin `wonsky-agents-update` skill delegates these mechanics to the script.
