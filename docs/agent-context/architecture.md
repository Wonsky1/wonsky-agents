# Architecture

The canonical collection is `skills/<name>/SKILL.md` plus each skill's scripts and references. `wa-using-dev-pipeline` routes work; Python's `wa-dev-pipeline` specializes `wa-unified-dev-pipeline`. Shared procedures live in their owning skill rather than being redefined by each worker template. Changes to a shared contract must reach its entry points, execution templates and review/completion gates.

`skills/explain/SKILL.md` defines the independent `wa-explain` entry point for plain-language explanations. Its default follows one concrete input through a system; brief requests get an overview, and detailed follow-ups expand only the selected step with intermediate data. The examples reference demonstrates a fictional RAG path and a matrix-to-vector calculation. It is not a development-pipeline stage and has no required external tool or agent dependency.

Draft — awaiting user review: skill metadata and invocation references use `wa-<slug>`. Canonical folder slugs and helper/link paths remain stable. `scripts/skills/names.py` maps those slugs to prefixed runtime folders for both installation and reviewed updates; runtime ownership records use the same prefixed name. Unknown unprefixed folders are preserved rather than assumed to belong to this collection; verified legacy copies migrate automatically as described below. The updater's runtime Keep choice for `wa-session-ledger` still prevents hook setup for that host.

`install.py` and `scripts/` install the collection into selected local agent destinations. Runtime copies are downstream outputs; lasting learning belongs in the canonical collection. Synchronization adds skills and records file hashes in `.wonsky-state/`. Conservative installation updates recorded files only when their installed bytes are unchanged; local edits or deletions block the affected unit, and extra or obsolete files remain. Unknown same-name copies require byte equality or an explicit trusted baseline. Existing `AGENTS.md` files are always retained. See the [installation documentation](../../README.md) for conflict reporting, baseline migration and platform limitations.

Repository context is an explicit pipeline deliverable. Useful factual context is written as a clearly marked draft at its intended path and then presented for user review; existing rules and proposed policies require exact approval before edits or activation. Root instructions stay small and this index selects cohesive topics without a fixed length limit. Task plans, test logs and chat summaries do not replace context. Draft review status, exact policy approvals and verified-current evidence travel in handoffs.

`update.py` adds an explicit review flow over original, local and offered skill files. Its preview shows file differences and whole-skill Keep/Use New choices across canonical and runtime destinations; reviewed replacements receive backups before apply. New code remains staged separately until the final plan is confirmed. Unknown originals are identified honestly, and existing AGENTS.md plus unrelated/personal files are preserved. The thin `wa-wonsky-agents-update` skill delegates these mechanics to the script.

## Session recovery and manual remote access

The wa-session-ledger helper separates identity and Markdown transformations from Git/storage operations, native hook adapters and CLI parsing. Its repository-local files have stable UUIDs and host-qualified session bindings. An exclusive mutation lock prevents concurrent create/bind writes. Git exclusion is checked before ledger writes and on reuse; plain directories are explicit and report the lack of Git verification. Hook adapters supply identity/lookup commands without shell exports. They are lazy and skip ambiguous multi-workspace selection.

Draft — awaiting user review: installation, synchronization and reviewed updates now include hook setup by default. `scripts/hooks/recovery.py` coordinates previews, configuration fingerprints, validation and application after accepted skills are installed. `scripts/hooks/setup.py` plans host changes using schemas in `scripts/hooks/definitions.py`; `scripts/hooks/files.py` owns file guards, backups and atomic replacements. Data lives in `scripts/hooks/models/plan.py`. Setup preserves unrelated configuration and refuses changed owned entries. Keeping wa-session-ledger skips its hook setup; `--no-session-hooks` skips setup for the current run. Configuration presence is not proof of host execution or Codex trust. The README records supported hooks and platform verification limits.

`scripts/skills/distribution.py` is the shared install/update boundary for wa-remote-server. Codex, Claude, Cursor and Copilot receive its explicit-only metadata. Antigravity and generic `.agents` destinations are excluded; existing unsupported copies are reported and preserved. The canonical skill remains available for explicit attachment. It contains no server-specific configuration and has no automatic router or hook trigger.

Updating source files does not retroactively change a running process.

## Runtime migrations and Copilot

Draft — awaiting user review: `scripts/migrations/registry.py` and `scripts/migrations/v0001_skill_namespace.py` owns an ordered registry with permanent IDs and read-only ownership/baseline checks; `scripts/migrations/models/plan.py` owns the per-skill plan. `scripts/migrations/review.py` binds review fingerprints and renders previews. `scripts/migrations/apply.py` backs up the complete old tree/state, renames both, writes a completion journal and rolls back a failed unit. The first migration is `0001-wa-skill-namespace`. Unchanged owned instructions or an exact explicit baseline establish identity; unknown folders stay, while edited owned instructions or colliding old/new destinations block before writes. Local extras move with the folder. Journals and backups live under each runtime skills root's `.wonsky-state/`.

Draft — awaiting user review: install/sync previews migrations automatically. The updater computes content diffs against the legacy tree, projects the prefixed destination into the existing update plan, binds migrations in the review report, validates old paths before applying and moves each accepted runtime unit before its content update. Keep skips that migration. Running old updater code cannot acquire this registry in the middle of its process; a trusted new download or a second invocation of the updated implementation supplies the new behavior.

Draft — awaiting user review: Copilot is an appended destination, detected by configuration, CLI or installed Copilot VS Code extensions. Personal skills use `~/.copilot/skills`; `COPILOT_HOME` overrides the CLI root. `scripts.hooks.setup.hook_config_path` locates the dedicated CLI file `hooks/wonsky-session-ledger.json`; its version-1 sessionStart handler uses direct exec/args. Ledger input accepts sessionId or session_id with conflicting aliases rejected and returns additionalContext. Personal skill support also applies to VS Code; automatic recovery setup is specifically for Copilot CLI.

## Python package ownership

Draft — awaiting user review: collection helpers are grouped into six packages under `scripts/`. `installation/` owns target detection, selection and the install CLI; `updates/` owns source acquisition, plans, review and application; `migrations/` owns its ordered registry, concrete versioned planners, review and guarded application; `hooks/` owns host schemas, setup, recovery and configuration writes; `skills/` owns collection copying, names and distribution; `filesystem/` owns shared ownership state, snapshots and guarded synchronization. Each data model lives in its owning package's `models/`. Initializers are inert and imports name defining modules.
